PROJECT CONTEXT

Full-stack prototype · Retrieval & review

01 / ENGINEERING PROBLEM

What the system needed to do.

Help operators respond using approved business knowledge while preserving human control over outgoing customer messages.

02 / ENGINEERING APPROACH

How the work comes together.

An authenticated Express API connects semantic retrieval over PostgreSQL/pgvector with response generation.

A Flutter inbox lets an operator review, edit, or approve the proposed response before the delivery step.

The repository includes mocked unit/integration tests, a React proof of concept, and a Docker Compose development environment.

03 / RESULT & SCOPE

What the work demonstrates.

A functional prototype with source and test infrastructure. Live messaging and AI services require configured external accounts; the website does not claim production deployment.

04 / KAREM WALED — RESPONSIBILITY

What I owned and contributed.

  • Designed and implemented the backend workflow and application integration.
  • Connected semantic retrieval, response generation, review states, and a messaging adapter boundary.
  • Built the Flutter operator inbox for editing and approval.
  • Added mocked unit/integration tests and a reproducible local development environment.

05 / SYSTEM BREAKDOWN

How the system is structured.

  • Knowledge is stored in PostgreSQL with pgvector-compatible embeddings.
  • An authenticated Express API retrieves relevant context and prepares a proposed answer.
  • The answer enters a review queue instead of being sent automatically.
  • A Flutter interface lets an operator inspect, edit, approve, or reject the draft.
  • A WhatsApp adapter layer represents the external delivery boundary.

06 / TECHNICAL IMPLEMENTATION

Engineering decisions and execution.

01

Retrieval

Queries are converted into a semantic search against approved business knowledge before drafting a response.

02

Human control

Review status is a first-class workflow state; the operator remains responsible for the outgoing message.

03

Testability

External AI and messaging services are isolated behind mocked boundaries so core workflow behavior can be tested locally.
