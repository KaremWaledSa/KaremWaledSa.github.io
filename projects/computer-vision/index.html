PROJECT CONTEXT

Computer-vision experiments

01 / ENGINEERING PROBLEM

What the system needed to do.

Connect visual detections to software and embedded behavior, while keeping capture, inference, data exchange, and output control understandable.

02 / ENGINEERING APPROACH

How the work comes together.

The archive includes SSD MobileNet and YOLO-family experiments for camera capture, preprocessing, inference, confidence filtering, and labeled overlays.

The public IoT bridge uses pretrained YOLOv5 detections, a Flask HTTP API, and ESP8266 polling to trigger an output for a configured object label.

The models are pretrained third-party models; this work focuses on application integration rather than original model training.

03 / RESULT & SCOPE

What the work demonstrates.

Detection scripts, an example API result, and an embedded client. No benchmark accuracy, latency, or custom-trained model results are claimed.

04 / KAREM WALED — RESPONSIBILITY

What I owned and contributed.

  • Implemented and studied Python/OpenCV detection pipelines using pretrained models.
  • Connected YOLOv5 output to a Flask HTTP service.
  • Implemented the ESP8266 polling and physical alert path.
  • Documented the difference between model integration and original model training.

05 / SYSTEM BREAKDOWN

How the system is structured.

  • Webcam capture feeds a Python inference process.
  • A pretrained YOLOv5 model returns labels, confidence values, and bounding boxes.
  • A Flask API stores and serves the latest detection result over the local network.
  • ESP8266 firmware polls the endpoint, parses the response, and activates an output when the target condition is met.

06 / TECHNICAL IMPLEMENTATION

Engineering decisions and execution.

01

Perception pipeline

Frames are captured, preprocessed by the model tooling, filtered by confidence, and converted into a structured result.

02

Software-to-hardware bridge

The backend exposes a small REST contract so the microcontroller does not need to run inference; it only consumes the decision data.

03

Configurable reaction

Target class and confidence threshold can be changed in firmware to drive an LED, buzzer, relay, or another suitable output.
