PROJECT CONTEXT

NTI capstone · Design & simulation

01 / ENGINEERING PROBLEM

What the system needed to do.

Explore driver-assistance behavior through sensor inputs, operating-mode logic, and actuator outputs on a constrained embedded controller.

02 / ENGINEERING APPROACH

How the work comes together.

The source separates register-level drivers, hardware interfaces, and application logic, including GPIO, timers, ultrasonic sensing, IR sensing, LCD output, and motor control.

An application state machine coordinates operating modes, sensor decisions, and warnings; UART provides a communication interface.

Proteus models the controller and connected devices. This is simulation work, not a road-tested vehicle or a certified safety system.

03 / RESULT & SCOPE

What the work demonstrates.

Team-written source code and a preserved simulation package. Precise ownership of individual modules is not established, so the case study credits the team implementation.

04 / KAREM WALED — RESPONSIBILITY

What I owned and contributed.

  • Contributed as one member of an approximately five-person team.
  • Participated in the complete firmware and simulation workflow; original per-file ownership was not recorded.
  • Can reproduce and explain the driver, application-state, Proteus, wiring, and integration work represented in the repository.

05 / SYSTEM BREAKDOWN

How the system is structured.

  • Application state machine selects stopped, low-speed, and high-speed behavior.
  • HC-SR04 input capture estimates obstacle distance; digital IR inputs support line-correction decisions.
  • PWM and GPIO outputs control two motor channels while LCD and buzzer states communicate warnings.
  • UART constructs a compact telemetry frame for speed and distance data.
  • Register-level MCAL modules provide GPIO, clock, SysTick, timer, and interrupt services.

06 / TECHNICAL IMPLEMENTATION

Engineering decisions and execution.

01

Layered firmware

The code separates MCU-facing drivers, reusable component interfaces, and application behavior so a state change does not directly manipulate every register.

02

Decision logic

Distance bands drive operating modes, while paired IR readings select forward motion, left correction, right correction, or stop behavior.

03

Simulation boundary

The controller and peripherals were connected and evaluated in Proteus. The project does not claim physical-road testing or functional-safety compliance.
