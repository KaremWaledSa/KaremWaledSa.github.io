PROJECT CONTEXT

NTI capstone · Design & simulation

01 / ENGINEERING PROBLEM

What the system needed to do.

Explore driver-assistance behavior through sensor inputs, operating-mode logic, and actuator outputs on a constrained embedded controller.

02 / ENGINEERING APPROACH

How the work comes together.

The source separates register-level drivers, hardware interfaces, and application logic, including GPIO, timers, ultrasonic sensing, IR sensing, LCD output, and motor control.

An application state machine coordinates operating modes, sensor decisions, and warnings; UART provides a communication interface.

Proteus models the controller and connected devices. This is simulation work, not a road-tested vehicle or a certified safety system.

03 / RESULT & SCOPE

What the work demonstrates.

Team-written source code and a preserved simulation package. Precise ownership of individual modules is not established, so the case study credits the team implementation.
