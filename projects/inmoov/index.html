PROJECT CONTEXT

Team graduation project · 2022

01 / ENGINEERING PROBLEM

What the system needed to do.

Develop an existing open-source humanoid into an integrated assistive platform. The engineering work spans joint actuation, wiring, robot description, perception, and mobile navigation.

02 / ENGINEERING APPROACH

How the work comes together.

Recovered Arduino sketches cover joint motion, fingers, shoulders, potentiometer mapping, and calibration. These show the hardware-facing side of the project.

Archived system material covers encoder odometry and IMU fusion, Kinect-based mapping, and the ROS 1 move_base navigation stack with global and local costmaps.

The manipulation workflow goes from a SolidWorks assembly to URDF, MoveIt configuration, and a rosserial interface sending joint commands to Arduino.

03 / RESULT & SCOPE

What the work demonstrates.

A documented team robot-development project with firmware, CAD, ROS visualizations, and physical integration evidence. The galleries show team-level system work without assigning every subsystem to one contributor.

04 / KAREM WALED — RESPONSIBILITY

What I owned and contributed.

  • Developed and calibrated Arduino-based motion experiments for fingers, shoulders, and articulated joints.
  • Worked across embedded actuation, mechanical assembly, wiring, and subsystem integration rather than treating each discipline in isolation.
  • Contributed to ROS and OpenCV experiments used to visualize, command, and extend the robot platform.
  • Supported integration and debugging as part of the graduation team; team-level results are clearly separated from individual contribution.

05 / SYSTEM BREAKDOWN

How the system is structured.

  • Mechanical layer: a life-size 3D-printed humanoid structure with articulated arms, hands, head, and a mobile base.
  • Embedded layer: Arduino-compatible controllers, servo actuation, potentiometer feedback and calibration routines.
  • Robot-model layer: CAD-derived geometry represented through URDF and visualized in RViz.
  • Manipulation layer: MoveIt configuration and joint-command flow toward the hardware interface.
  • Perception and mobility layer: camera experiments, odometry/IMU concepts, mapping, costmaps, and the ROS navigation workflow.

06 / TECHNICAL IMPLEMENTATION

Engineering decisions and execution.

01

Motion and calibration

Recovered sketches expose how commanded positions, mapped potentiometer readings, servo limits, and joint-specific routines were used to make physical motion repeatable.

02

Robot description and manipulation

The workflow connects mechanical assemblies to a URDF robot model, checks the model in RViz, prepares it in MoveIt, and routes joint commands toward embedded controllers.

03

Mobile robotics stack

The wider team system includes map generation, localization-related sensor inputs, global/local cost representations, and movement planning for the mobile platform.

04

Integration reality

The strongest engineering lesson was at the interfaces: mechanical tolerances affect calibration, wiring affects motion reliability, and software assumptions must match the physical robot.
